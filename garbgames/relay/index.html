GBM · garbsoftball.com → Hugging Face bucket

580 games (~48 GB) get mirrored to smodusermc/garbsoftball-games by two console scripts you paste — one per tab. This relay is the byte pipe between them.

1 Tab A — crawl (garbsoftball.com)

Open https://garbsoftball.com/g in a new tab. Press F12 → Console, then paste Script A below and hit Enter. The green dashboard (top-right of that page) shows progress. Keep that tab open.
It crawls each game from the inside out (same-origin, so nothing is blocked), streams every file to this relay, and remembers progress — if you close it, just re-paste and it resumes.

2 Tab B — upload (huggingface.co)

Open https://huggingface.co/buckets/smodusermc/garbsoftball-games in another tab (if it 404s, no problem — the script creates it). Press F12 → Console, paste Script B and hit Enter, then paste your HF token when prompted. The blue dashboard (bottom-right) shows upload progress.
The token is sent only to huggingface.co (from that tab, by the official Hugging Face JS SDK) — it never touches this relay. Uploads resume if you re-paste Script B.

Fallbacks & notes

  • If the relay ever goes offline mid-crawl, Tab A automatically switches to ZIP mode — zips (~1.4 GB each) download to your machine. Just drag them onto the bucket page in the HF web UI and you're done; nothing is lost.
  • Speed is bound by your downlink (site → you) and uplink (you → HF). Roughly: your uplink × run-time ≈ total bytes, so ~100 MB/s up finishes in well under an hour; 20 MB/s ≈ ~40 min.
  • Proxied games (24 of 604) are live third-party sites — they're skipped by design and listed in the manifest inside the bucket.
  • Both scripts are resumable from any interruption (network, sleep, browser crash). The relay keeps up to 8 GB queued; Tab B drains it as fast as HF accepts commits.
Security: what this relay sees
The relay receives only (a) game file bytes and (b) progress beacons. It never receives your HF token, cookies, or anything from huggingface.co. The upload tab talks to huggingface.co directly (same-origin, the SDK's normal Xet flow); the relay merely hands it file bytes.
